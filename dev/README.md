## App Mac (Electron) : structure, lancement, build

Structure du dépôt :

- `index.html`, `js/`, `lib/`, `fonts/` : le jeu, inchangé, toujours jouable seul dans un navigateur (ouvrir `index.html`).
- `electron/main.js` : l'enveloppe. Une fenêtre (1440 × 900, plein écran : menu Affichage ou Ctrl+Cmd+F) qui charge `index.html` depuis le disque. Hors ligne strict : toute requête autre que `file:`, `data:`, `blob:` est annulée et notée dans `global.lpBloquees` ; pas de fenêtre secondaire ni de navigation. Son : `autoplay-policy=no-user-gesture-required` plus un faux `keydown` au chargement, qui déclenche l'`eveil` de son.js sans toucher au jeu. Menu Affichage → « Ouvrir le dossier des sauvegardes ».
- `electron/test-app.js` : test de l'app (voir plus bas).
- `package.json` (racine) : Electron, electron-builder, réglages du build (`build.files` : seuls `index.html`, `js`, `lib`, `fonts`, `electron/main.js` entrent dans l'app ; `dev/` n'y est pas).
- `dev/` : cette fiche, tests jsdom et outils de capture (son propre `package.json`).
- `dist/` : produit par le build, jamais commité.

Commandes, depuis la racine (Node 20 ou plus) :

- `npm install` : une fois.
- `npm start` : lance le jeu dans sa fenêtre.
- `npm run test:app` : deux lancements de suite dans un dossier de données temporaire ; vérifie page locale, scripts, six familles de polices, son `running` sans clic et signal mesuré, partie enregistrée puis retrouvée après relance, réglages gardés, aucune requête réseau, plein écran. `échecs: 0` attendu. Sous Linux sans écran : `xvfb-run -a npm run test:app`. `SRC=<app.asar>` teste le contenu d'une app construite ; `SHOT=<fichier.png>` garde une capture.
- `npm run build` : construit `dist/mac-arm64/La Permanence.app` (Mac Apple Silicon) et `dist/mac/La Permanence.app` (Mac Intel). `npm run build:zip` : les mêmes en `.zip`.

Signature : pas de certificat Apple (usage personnel). Construit **sur un Mac**, l'app reçoit une signature locale (`identity: "-"`) et s'ouvre directement. Construit **sous Linux** (session cloud), aucune signature n'est possible : sur le Mac, lancer une fois dans le Terminal `xattr -cr "La Permanence.app" && codesign --force --deep --sign - "La Permanence.app"`, sinon macOS annonce une app « endommagée ». Icône : celle d'Electron par défaut (mettre un `build/icon.icns` pour la changer).

### Moteur génératif : ce qu'il faut savoir

- Une affaire générée est un tirage `p.t` stocké dans `s.generated` (≈ 1,9 Ko) ; la définition est reconstruite au chargement (`CR.restoreGenerated` → `GEN.build` → `GEN2.def`). La signature (`t.sig`) et `p.client` sont recalculés, jamais sauvegardés. Les pièces tirent leurs détails d'une graine propre à chaque pièce (`t.sig + ":" + clé`) : elles se relisent à l'identique.
- Ajouter une infraction voisine d'une fiche existante : une variante dans `cat-lot1.js` (`variantes(id, p, { sc: { poids, tirer, qual, recit, requalif, scn } })`) ; le moteur lit la scène par `CAT.ficheDe` (tirage, victime, nom et notions, convocation, catégorie des questions). Une fiche peut décrire ses images (`N.video` : titre, source, scène, identification) et ses écrits (`N.ecritsPiece` : titre, introduction, dates ou non) quand ce ne sont ni une caméra de rue ni des messages de téléphone. Tests ciblés : `tests/tgen_lot1.js` et `tests/tdial_lot1.js` (mêmes tests que `tgen` et `tdialogues`, seulement sur les variantes).
- Ajouter une infraction : une fiche `CAT.def(id, { fam, nom, textes, elements, mesures, flagrance, voies, preuves, irr, tirer, qual, recit… })` (modèle : `cat-lot2.js`), ses textes dans `CAT.TEXTES` s'ils manquent, sa fréquence dans `GEN2.FREQ` ; attention, chaque élément de `f.agg` ajoute sa circonstance à la prévention (`CAT.aggPrev`) : un élément constitutif (la vulnérabilité de l'abus de faiblesse) n'y va pas ; la prévention suit « d'avoir, à …, » et commence par un participe passé ; éviter « les petits », « mon enfant », « mon travail »… dans les répliques si la fiche de la personne ne le dit pas (`tests/tcoherence.js`) ; `tests/tgen.js` vérifie le reste. Un crime : `C.fiche(id, { fam, nom, textes, elements, qual, requalif, ctxs })` dans un `cat-crimes-*.js` ; chaque contexte porte ses personnes, preuves, enjeux et récits ; la juridiction et le plan de l'information viennent de `gen-instruction.js`.
- Dialogues : toute réplique d'une affaire générée passe par `gen-parole.js`. Dans les fiches, jamais de pronom ni d'accord en dur pour une personne dont le genre n'est pas fixé par le contexte : `X.il(P)`, `X.Il(P)`, `X.e(P)`, `X.lui(P)` (tonique), `X.la(P)` (le/la), `X.g(P).w("le conducteur", "la conductrice")` ; dans les textes statiques des enjeux et des mobiles (crimes), les jetons `{il}`, `{Il}`, `{e}`, `{le}`, `{lui}`, `{mex}`, `{Mex}`, `{dumex}`, `{sil}`, `{seul}`, `{Vil}`, `{VIl}`, `{Ve}`, `{Vla}`, `{Vlui}` (`CAT.enjeuTexte`, `CAT.enjeu(id, A, V)`). `CAT.typo` ne contracte plus « de le » devant un infinitif (« de le faire »). `tests/tdialogues.js` attrape le reste.
- Contenu : passer par `X.lex(…)` pour les mots crus ; violences sexuelles décrites de façon clinique. **Règle assouplie à la demande de Kevin le 12 novembre 2026, pas encore codée** (section « Contenus durs : règles assouplies » de `dev/ref/refonte-gameplay.md`) : les affaires de mineurs victimes d'infractions sexuelles cessent d'être réduites à la procédure et deviennent des dossiers complets, écrits comme de vraies pièces (faits qualifiés, audition de l'enfant en substance avec quelques mots cités quand ils portent un enjeu, examen médical, expertises, messages décrits par l'enquêteur, questions de droit propres, nom de l'enfant dans les pièces). Limites qui restent fermes : aucune description sexualisée, sensorielle ou détaillée d'actes sur un mineur, aucune reproduction de messages sexuels adressés à un mineur, aucune image ni description d'images d'un mineur victime. Un mode adouci remplacera `CAT.LEX` et les passages marqués, sans toucher aux fiches.
- Directeur de partie : en carrière, les affaires générées ne suivent plus la première graine nouvelle mais le choix de `GEN2.DIR` ; les tests qui rejouent des scénarios de référence le coupent (`CR.GEN2.DIR.off = true`, comme `tests/tgenjeu.js`).
- Les nouveaux clients viennent surtout du générateur (`CR.dailyLeads`, `GEN2.LEADS`) ; chaque affaire écrite (hors ouverture) manque à une partie sur deux (`CR.VIVIER_ABSENCE`).
- Saisie des articles : codes ajoutés CSP, C. com., CGI et CJPM (`citations.js`).
- Code annoté : le plan vient des tables des matières de codes.droit.org (générées depuis Légifrance ; Légifrance et Judilibre refusent la lecture automatique). Le CSP n'a pas pu être relu : intitulés marqués « à revérifier ». Les arrêts du premier lot sont vérifiés sur le texte intégral (assemblée plénière 2011, Crim. 19 oct. 2010) ou sur des commentaires (les autres) : la source et la date sont dans `verif`, et la fiche invite à lire le texte intégral sur Judilibre. Les six arrêts plus anciens du jeu restent « à vérifier ». Un nouvel article de la bibliothèque est rangé automatiquement s'il tombe dans une plage connue ; sinon `tests/tbiblio.js` le signale (« non rangé »).
- Cour criminelle départementale et récidive : un seul réglage, `CR.CCD_RECIDIVE` dans `law-fr.js` (false : hors récidive, choix de la phase 2 ; true : récidive comprise, version de l'affaire n° 12 et de l'art. 380-16 qui citaient la loi du 23 juillet 2026) ; `CAT.CCD_HORS_RECIDIVE` en est le reflet ; le texte de l'art. 380-16, les fiches de a12 et de l'instruction, les sources suivent. À revérifier sur Légifrance. Autres choix de la phase 2 à revérifier : appel d'un arrêt de CCD devant une cour d'assises d'appel (9 jurés) ; trafic criminel devant la cour spécialement composée ; paliers de l'incendie (322-7 à 322-10) ; numérotation du CJPM ; période de sûreté appliquée à toute réclusion de dix ans ou plus. Les durées d'une information sont resserrées (quelques mois à un an et demi de jeu).
- Équipe : chaque chiffre de droit du travail ou de déontologie est dans `CR.EQ_CHIFFRES` (affiché dans l'onglet « Chiffres à revérifier ») ; le temps de l'équipe s'ajoute à `cs.worked` (élève à moitié, assistante non facturée) et se lit dans `cs.workedBy`.
- N° 12 : une affaire générée peut compter plusieurs infractions (`t.conc`) ; le maximum encouru est le plafond par nature (`t.enc`), jamais la somme ; un même fait poursuivi deux fois (`memeFait`) peut être écarté. La récidive n'est appliquée que si `CAT.etatLegal` la constate, ou si le parquet se trompe (`t.recid.vice`, lisible au bulletin n° 1 : dates de jugement, de définitivité, de fin de peine, qualification) ; la défense la discute à l'audience (choix réservés à qui a noté `G_ant`). La société cliente parle par son représentant (`t.R`) ; l'amende est quintuplée ; la délégation de pouvoirs ne la protège jamais. Codes LPF et CSI ajoutés à la saisie ; articles nouveaux dans `CAT.TEXTES` (fin de `cat-base.js`), tous « à revérifier ».
- Phase 3 : le lieu des faits (`t.lieu`) décide du commissariat et du tribunal judiciaire (Paris, Bobigny, Créteil, Nanterre : `def.tj`) ; domicile, métier, revenus et montants suivent le secteur et le milieu. Les personnages (`t.vie`, `GEN2.tirerVie`) sont tirés sur un fil de hasard à part (graine + « :p3 ») : les tirages d'avant ne bougent pas. Le droit des affaires n'a pas changé.
- Signature et code sont distincts : la signature (`t.sig`) identifie le tirage ; le type (`GEN2.typeSig` : infraction, contexte, preuves, irrégularité, camp) entre dans l'historique `GEN2.HIST_KEY` (« la-permanence-historique-v1 » dans le navigateur, copie dans chaque sauvegarde `s.genTypes`, document « historique » dans le nuage) ; `GEN2.params` écarte un type déjà joué, puis fait varier contexte et preuves quand une famille est épuisée.
- Code d'affaire (`PEN-7K4Q-9XF2`) : trois lettres du genre, 35 bits (version du générateur, jour, créneau, numéro) mélangés de façon réversible, alphabet Crockford sans I, L, O, U, lettre de contrôle CRC-5 (toute faute de frappe ou interversion de deux caractères voisins est refusée) ; graine `v1:genre:jour:créneau:n`. Version actuelle : 3 (lot 1 du programme ; les codes des versions 1 et 2 sont refusés). Les nouvelles graines ont révélé trois hypothèses fausses des tests, corrigées : une société cliente n'a pas de discussion de récidive (`tgen.js`), une commission d'office n'a pas de refus ordinaire (`tp3.js`), un appel du parquet peut suivre le jugement (`tgenjeu.js`) ; `court.js` prend le premier angle quand l'angle voulu manque. **Toute modification du tirage (gen-moteur, gen-monde, cat-*, gen-instruction) qui change une affaire tirée d'une graine impose d'incrémenter `GEN2.VERSION` ; `GEN2.VERSIONS_LISIBLES` ne garde que les versions qui se rejouent encore à l'identique** : un code d'une autre version est refusé, jamais remplacé par une autre affaire. Une partie « affaire » (`s.mode = "affaire"`) a son propre emplacement de sauvegarde et ne touche pas la carrière.
- Choisir ses dossiers (`systems.js`) : au premier contact, accepter, refuser (`CR.refuserDossier` : aucun honoraire, du temps libéré, réputation entamée si la réponse tarde ou si l'affaire est urgente) ou transmettre à un confrère (`CR.transmettreDossier` : relation et réputation auprès des confrères, renvoi d'ascenseur plus tard, `CR.GLOBAL_FN.ascenseur`) ; une commission d'office ne se refuse que pour un motif légitime.

### Mesurer la répétition (9 novembre 2026, après le lot 4)

Deux affaires prises deux à deux ne disent plus grand-chose : sur le chemin réellement joué d'une carrière simulée (appels, pièces, audience principale), la part du texte déjà lu est de 8 % par rapport à l'affaire précédente, 30 % sur les cinq dernières, 45 % sur les dix dernières, 69 % sur toute la carrière ; pour les choix, 14 %, 40 %, 60 % et 85 %. Le phrasier et ses variantes ne font presque plus bouger ces chiffres : ce qui reste, ce sont les choix fixés par la procédure (questions de l'avocat en garde à vue, motifs de refus d'une commission d'office, accepter d'être jugé ou demander un délai, dernier mot) et les récits d'une même infraction dans une même scène. Prochaine étape : de nouveaux choix tirés des faits, pas de nouvelles phrases.

## 5. Livrer

Plus de publication en artifact : on commite et on pousse sur le dépôt Git, puis `npm run build` pour refaire l'app. `index.html` est un document complet (il garde en première ligne l'enveloppe héritée de l'artifact : ne pas la supprimer). Toute CSS nouvelle se met avant le DERNIER `</style>`.

## 6. Règles du projet

- Droit : faire des recherches en ligne dès que c'est nécessaire pour être quasi certain de ce qu'on met dans le jeu (texte en vigueur, peine, rédaction d'un article, jurisprudence), sans attendre l'accord de Kevin : Légifrance et Judilibre d'abord, puis sources officielles (service-public.fr, ministère de la Justice). Un texte vérifié est marqué avec la date et la source de la vérification ; ce qui n'a pas pu l'être reste marqué « à revérifier ». Depuis le 10 novembre 2026, il ne reste aucun « à revérifier » sur une règle précise : seulement l'avertissement général (résumés à relire avant tout usage réel).
- Économie de tokens : lectures ciblées, plusieurs modifications par appel, au plus une capture de contrôle par livraison, pas de boucle de retouches sans demande.
- Après un chantier : cocher la case dans la feuille de route, commiter, faire tourner `npm run test:app`, t1, t17 et les tests des affaires touchées.
